## Context

`sdf_config`, `sdf_platform`, and `sdf_platform_power` are all already members of `firmware/test_runner`'s build graph (`EXTRA_COMPONENT_DIRS`/`COMPONENTS` in `firmware/test_runner/CMakeLists.txt`) and already build cleanly for `IDF_TARGET=linux` — `sdf_platform`'s `CMakeLists.txt` opens with an explicit `if(IDF_TARGET STREQUAL "linux")` branch, and neither `sdf_config` nor `sdf_platform_power` has any hardware-only `REQUIRES` at all. `openspec/specs/firmware-host-test-runner/spec.md`'s "Wired-In Component Coverage" requirement doesn't list them today only because nobody has written a `RUN_TEST()` for them yet — this is coverage-writing, not build-graph work.

Inspecting the actual source clarifies what's realistically testable:

- **`sdf_config`**: a flat getter (`sdf_config_get()`) plus per-field setters (`sdf_config_set_checkin_interval`, `_set_failed_attempt_threshold`, `_set_battery_default_percent`, `_set_lockout_duration`, etc., `firmware/components/sdf_config/src/sdf_config.c`). Each setter validates its argument (e.g. `sdf_config_set_checkin_interval` rejects `< 1000` or `> 600000`; `sdf_config_set_failed_attempt_threshold`/`_set_lockout_duration` reject `0`; `sdf_config_set_battery_default_percent` rejects `> 100`) and returns `ESP_ERR_INVALID_ARG` on rejection, `ESP_ERR_INVALID_STATE` if called before init. This is pure, deterministic validation logic — straightforward Unity material.
- **`sdf_platform`**: three sub-APIs. GPIO (`sdf_platform_gpio.h`) and NVS (`sdf_platform_nvs.h`) wrap thin, already-linux-mocked calls (`sdf_common`'s `sdf_mock_linux_gpio.c` stubs `gpio_set_level`/`gpio_get_level`/etc. to fixed return values under `CONFIG_IDF_TARGET_LINUX`). Sleep (`sdf_platform_sleep.h`) is a mixed bag: pure/deterministic functions (`sdf_platform_map_wakeup_reason`, `sdf_platform_sleep_configure_wake_sources`, `sdf_power_crc16_ccitt`) sit alongside functions that are trivial no-ops on `linux` by design (`sdf_platform_sleep_retention_write/read/valid` compile out to `return ESP_OK`/`false` under `CONFIG_IDF_TARGET_LINUX` since there's no real RTC retention memory) and two functions that call real ESP-IDF sleep entry points unconditionally: `sdf_platform_sleep_light()` → `esp_light_sleep_start()` and `sdf_platform_sleep_deep()` → `esp_deep_sleep_start()`. Neither has a `CONFIG_IDF_TARGET_LINUX` guard in `sdf_platform_sleep.c`.
- **`sdf_platform_power`**: a thin 7-function facade over `sdf_platform_sleep`. One function, `sdf_platform_power_gate_ble_radio()`, unconditionally returns `ESP_ERR_INVALID_STATE` regardless of its `enable` argument — this reads as an unimplemented stub, not a bug introduced by this change, and is not this change's job to fix.

## Goals / Non-Goals

**Goals:**
- Write Unity suites for `sdf_config`, `sdf_platform` (GPIO/NVS/sleep wrappers), `sdf_platform_power`, and web-user storage that exercise every branch reachable safely under `IDF_TARGET=linux`.
- Wire all of them into `test_runner` so `firmware-host-test-runner`'s "Wired-In Component Coverage" requirement can be truthfully extended to list all three components.
- Pin down the two known-odd behaviors found above (`sdf_platform_power_gate_ble_radio()`'s unconditional `ESP_ERR_INVALID_STATE`, and retention functions' linux no-op semantics) as explicit, named test cases — so a future change to either is a deliberate spec change, not a silent regression.

**Non-Goals:**
- Calling `sdf_platform_sleep_light()`/`sdf_platform_sleep_deep()` (and therefore `sdf_platform_power_enter_light()`/`_enter_deep()`) from a Unity test. Both hit real ESP-IDF sleep entry points with no linux guard; `esp_deep_sleep_start()` does not return on real hardware and `esp_light_sleep_start()` depends on a configured wake source to return at all — invoking either from a test process risks hanging or terminating the test runner rather than exercising fakeable logic. These four functions are left uncovered by direct call; test what precedes them instead (`enable_gpio_wake` argument plumbing, which just configures state and returns before any sleep entry point is reached).
- **(Discovered during implementation, empirically, via a real build — not anticipated when this design was first written.)** Calling `sdf_platform_sleep_enable_timer_wakeup()` (and therefore `sdf_platform_power_enable_timer_wake()`), `sdf_platform_sleep_disable_all_wakeup_sources()` (and `sdf_platform_power_disable_all_wake()`), or `sdf_platform_sleep_configure_wake_sources()` **with any argument** from a Unity test. All three are unconditional, linux-unguarded passthroughs to (or, for `configure_wake_sources()`, unconditionally reference in their compiled object code) the real `esp_sleep_enable_timer_wakeup()`/`esp_sleep_disable_wakeup_source()`. Neither symbol is compiled into `esp_hw_support`'s `IDF_TARGET=linux` build (that target's `CMakeLists.txt` only builds `port/linux/esp_random.c` + `port/linux/chip_info.c`), so referencing them from any reachable code path — regardless of which runtime branch is actually taken — is a **link failure**, not just a runtime risk like `sleep_light()`/`sleep_deep()` above. This is a stricter exclusion than originally planned: it rules out `configure_wake_sources()` entirely (not just its `SDF_WAKE_SRC_TIMER` case) and both `enable_timer_wake`/`disable_all_wake` on `sdf_platform_power`.
- **(Also discovered empirically.)** Calling `sdf_platform_nvs_init()` at all. Its object code unconditionally references `nvs_flash_read_security_cfg()`/`nvs_flash_generate_keys()` inside a runtime-dead (`keys_partition == NULL` on linux) but link-time-live branch. Those symbols live in the `nvs_sec_provider` component, which `nvs_flash`'s own `CMakeLists.txt` deliberately excludes from its linux-target `REQUIRES` ("mbedtls isn't configured for building with linux ... it will draw in all kind of dependencies") — this is an upstream ESP-IDF linux-target limitation, not a gap in `sdf_platform`. NVS coverage here is limited to `sdf_platform_nvs_get_security_status()`/`_security_ok()`/`_erase_all()`'s pre-init behavior, none of which require `_init()` to have run.
- Fixing `sdf_platform_power_gate_ble_radio()`'s apparent stub behavior, or changing any other production logic. This change only adds tests around existing behavior, including behavior that looks unfinished.
- Testing `sdf_config_save()`/NVS persistence round-trips through real flash — `sdf_config`'s NVS-backed persistence is exercised (if at all) through `sdf_platform_nvs`'s own coverage below; `sdf_config`'s suite here is scoped to the in-memory getter/setter validation surface.
- `sdf_ota` and `sdf_ble_companion`/web-auth coverage — out of scope, tracked by the sibling changes `spike-sdf-ota-linux-target` and `add-linux-target-sdf-app-support`.

## Decisions

**One test file per component, following the repo's existing `test_sdf_<component>.c` naming (`firmware/components/<name>/test/test_sdf_<name>.c`).**
Matches every other component's convention already visible in `test_runner/main/CMakeLists.txt`'s `SRCS`.

**`sdf_platform`'s single suite covers all three sub-APIs (GPIO/NVS/sleep) rather than three separate files.**
`sdf_platform.h` presents them as one component with one public surface; splitting the test file would fragment coverage of a component that's small enough (three headers, a couple hundred lines of implementation) not to need it. Precedent: `sdf_services`'s test file structure is split by *implementation* file (`_match`, `_enroll`, ...) but `sdf_platform`'s implementation files are thin enough that one `test_sdf_platform.c` with clearly-named test functions per sub-API reads just as clearly.

**Sleep no-ops (`retention_write/read/valid` under linux) are tested for their actual linux behavior (`ESP_OK`/`false`), not skipped.**
Alternatives considered: skip them entirely since "there's nothing to test." Rejected — if a future change accidentally adds real linux-side retention emulation or changes the no-op return value, a currently-passing test should fail and force an explicit look, rather than the change going unnoticed because no test ever asserted the no-op contract.

**Web-user storage coverage is added to the existing `test_sdf_storage.c`, not a new file.**
It's already a wired, already-passing suite covering every other storage-key family (`sdf_storage_web_user_*` is the only omission); adding to it is strictly additive and keeps one canonical storage test file rather than splintering by key-family.

**`sdf_platform_power_gate_ble_radio()`'s stub-like `ESP_ERR_INVALID_STATE`-always behavior gets one test case pinning current behavior, with a comment flagging it as apparently-unimplemented rather than presenting it as intentional.**
Alternatives considered: leave it untested to avoid encoding what might be a bug into a "passing" test suite. Rejected — an untested public function is worse than a test that says, in effect, "this currently always errors; if that's surprising, it's pre-existing, not something this change introduced or endorses."

## Risks / Trade-offs

- [Calling `esp_light_sleep_start()`/`esp_deep_sleep_start()` from a linux-target Unity test could hang or kill the test binary, silently blocking CI] → Addressed by the Non-Goal above: these two functions (and their `sdf_platform_power` wrappers) are excluded from direct-call coverage. If a future change wants to test them, it needs a `linux`-specific mock of the underlying `esp_*_sleep_start()` calls first (mirroring `sdf_mock_linux_gpio.c`'s pattern) — out of scope here.
- [Testing a stub (`gate_ble_radio`) risks the test suite looking like it's asserting "always-error is correct behavior"] → Mitigated with an explicit code comment on that test case noting the apparent-stub status, so a future implementer isn't misled into thinking the always-`ESP_ERR_INVALID_STATE` return is a deliberate contract to preserve.
- [`sdf_config`'s setters mutate global config state (`sdf_config_get_mutable()`); tests running in sequence in the same process could leak state between cases] → Follow the existing `ensure_services_initialized()`-style pattern from `test_sdf_services.c`: a `setUp()`/`tearDown()` (or explicit reset call, if `sdf_config` exposes one) that resets to known defaults before each test case.
- **(Discovered during implementation.)** [`sdf_config_get_mutable()` returns `NULL` unless `CONFIG_SDF_CONFIG_ENABLE_RUNTIME_OVERRIDE` is enabled (default `n` in production Kconfig), which would make every setter short-circuit to `ESP_ERR_INVALID_STATE` before its actual bounds-validation logic ever runs] → `firmware/test_runner/sdkconfig.defaults` now sets `CONFIG_SDF_CONFIG_ENABLE_RUNTIME_OVERRIDE=y`, test-only, matching the existing precedent of overriding Kconfig defaults there for testability (e.g. `CONFIG_SDF_ZIGBEE_ENABLE=n`).
- **(Discovered during implementation, via a real build — see the Non-Goals above.)** [`sdf_platform_sleep_enable_timer_wakeup()`/`_disable_all_wakeup_sources()`/`_configure_wake_sources()` and `sdf_platform_nvs_init()` reference ESP-IDF symbols (`esp_sleep_enable_timer_wakeup`, `esp_sleep_disable_wakeup_source`, `nvs_flash_generate_keys`, `nvs_flash_read_security_cfg`) that aren't compiled into their respective components' `IDF_TARGET=linux` builds, so calling them from a test fails at *link* time, not just at runtime] → These calls are excluded from direct-call coverage (see Non-Goals). Confirmed empirically: an initial build attempt that did call them failed with `Undefined symbols for architecture arm64`, not a runtime error.

## Migration Plan

1. Add `firmware/components/sdf_config/test/test_sdf_config.c`: setter bounds-validation (accept-at-boundary, reject-just-outside-boundary, reject-zero where applicable) for `checkin_interval_ms`, `failed_attempt_threshold`, `failed_attempt_window_ms`, `lockout_duration_ms`, `battery_default_percent`. The "called before init" case turned out not to be reachable (see task list) — `sdf_config_get_mutable()` gates purely on `CONFIG_SDF_CONFIG_ENABLE_RUNTIME_OVERRIDE`, not init state, and `test_runner_main.c` always calls `sdf_config_init()` before any `RUN_TEST()`; documented in-code instead of as a test case.
2. Add `firmware/components/sdf_platform/test/test_sdf_platform.c`: GPIO wrapper pass-through against the linux mock's fixed returns (`sdf_platform_gpio_set_level`/`_get_level` against `gpio_set_level`/`gpio_get_level`'s mocked constants), `sdf_platform_gpio_is_rtc_capable()`'s GPIO 0–7 boundary, `sdf_platform_map_wakeup_reason()`'s full enum mapping, `sdf_power_crc16_ccitt()` against a known test vector, and the linux no-op contracts for `sdf_platform_sleep_retention_write/read/valid` and `sdf_platform_sleep_wakeup_from_gpio/_timer/_usb` (all `false`/no-op under `CONFIG_IDF_TARGET_LINUX`). `sdf_power_crc16_ccitt()` needed a missing declaration added to `sdf_platform_sleep.h` (it was defined but never declared in any header) — a header-only fix, no behavior change. `sdf_platform_sleep_configure_wake_sources()` and `sdf_platform_nvs_init()` are **not** called (see Non-Goals: both fail to link on `IDF_TARGET=linux`); NVS coverage is limited to `_get_security_status`/`_security_ok`/`_erase_all`'s pre-init behavior.
3. Add `firmware/components/sdf_platform_power/test/test_sdf_platform_power.c`: `enable_gpio_wake` argument plumbing (delegates correctly to the underlying `sdf_platform_sleep_*` call's return code), and the `gate_ble_radio()` always-`ESP_ERR_INVALID_STATE` pin (commented as apparently-unimplemented). `enable_timer_wake`/`disable_all_wake` are **not** called (see Non-Goals: both fail to link on `IDF_TARGET=linux`, same as `enter_light()`/`enter_deep()`).
4. Extend `firmware/components/sdf_storage/test/test_sdf_storage.c` with web-user cases: save/load round-trip, load-not-found, find-by-name hit/miss, clear, clear_all, count, and the `SDF_STORAGE_WEB_USER_MAX` slot-boundary (save succeeds up to the max, then fails/rejects on overflow — confirm actual behavior from `sdf_storage.c` while writing the test rather than assuming). `find_by_name`'s miss case and `count`'s empty case both need an unrelated entry saved first — `nvs_open(..., NVS_READONLY, ...)` on a namespace that's never been written to fails with `ESP_ERR_NVS_NOT_FOUND` before either function's own "not found"/zero-count logic is ever reached; discovered empirically while writing these tests, documented in-code.
5. Wire every new/extended `RUN_TEST()` into `firmware/test_runner/main/test_runner_main.c`; add new `SRCS` entries to `firmware/test_runner/main/CMakeLists.txt` for the two new files (`test_sdf_config.c`, `test_sdf_platform.c`, `test_sdf_platform_power.c` — `test_sdf_storage.c` is already listed).
6. Run `./build/sdf_test_runner.elf` from `firmware/test_runner`, confirm 100% pass, confirm no hang (validates the Non-Goal exclusions were sufficient).
7. Extend `firmware-host-test-runner`'s "Wired-In Component Coverage" requirement to list `sdf_config`, `sdf_platform`, `sdf_platform_power` alongside the existing entries.
8. Rollback is a plain revert — no production code changes besides the one-line header declaration in step 2 and the test-only Kconfig default in Risks above; no data migration, nothing to unwind at runtime.

## Open Questions

- Should `sdf_platform_sleep_light()`/`_deep()` eventually get a `linux`-target mock (following `sdf_drivers`'/`sdf_protocol_zigbee`'s `*_mock_linux.c` pattern) so their argument-validation paths (if any exist beyond the current unconditional pass-through) become testable too? Not resolved here — flagged as a possible follow-up once `spike-sdf-ota-linux-target` establishes whether this repo wants to invest further in `*_mock_linux.c`-style hardware mocking.
- Does `sdf_storage_web_user_save()` reject or silently overwrite when all `SDF_STORAGE_WEB_USER_MAX` slots are full? The proposal names this as a boundary to cover but the exact current behavior needs confirming from `sdf_storage.c` during implementation, not assumed here.
