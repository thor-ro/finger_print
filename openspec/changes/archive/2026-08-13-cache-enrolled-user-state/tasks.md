- [x] 5.2 Enrollment completion (`sdf_services_enroll.c:140-154`, `SDF_ENROLL_ACT_COMPLETE`): set the user's bit and permission in the cache, call the persist helper; on persist failure after retries exhausted, call `fp_delete_user()` to roll back the sensor-side enrollment, do not advance the cache bit, report enrollment as failed (not `SDF_ENROLL_ACT_COMPLETE` success), and trigger `led_flash_red()`

- [x] 7.1 Unit test: `sdf_services_init()` loads the cache from NVS before any task starts, and a task reading enrolled-user state immediately after `sdf_services_init()` returns sees the persisted value (regression test for the boot race this change fixes) - `test_sdf_services_init_loads_enrolled_users_cache_before_return`
- [x] 7.2 Unit test: `sdf_button_dispatch_action()` never takes the "0 users, execute immediately" branch on a device with a persisted enrolled admin, including when invoked as the very first action after `sdf_services_init()` - `test_button_dispatch_never_bypasses_gate_as_first_action_after_init`
- [x] 7.3 Unit test: `sdf_services_enrolled_user_count()` helper returns the correct population count for various bitmap values - `test_enrolled_user_count_{zero_bitmap,single_bit,multiple_bits,all_ten_users,updates_after_clear}`
- [x] 7.4 Unit test: enroll/delete/clear/permission-change each update the cache and call the persist helper before reporting success - decision: the four mutation paths (`sdf_services_enroll.c` completion, `sdf_services_delete_user`, `sdf_services_clear_all_users`, `sdf_services_change_user_permission`) are only reachable past a successful `fp_*()` sensor call, and the Linux host mock UART can never produce one (see `test_fingerprint_owner_task.c`'s own comment: "The mock UART never produces a valid frame, so this can't succeed"). Extending the Linux mock fingerprint driver to force success is out of scope for this change (touches `sdf_drivers`/`sdf_mock_linux_drivers.c`, not in its Impact list). Substituted direct coverage of the shared primitive all four paths funnel through, `sdf_services_persist_enrolled_users_locked()`, via a new `SDF_STORAGE_TESTING` fault-injection seam in `sdf_storage_enrolled_users_save()`: `test_persist_enrolled_users_locked_writes_current_cache_to_nvs`
- [x] 7.5 Unit test: enrollment with a simulated persistent NVS write failure rolls back the sensor-side enrollment, reports failure, and triggers the red LED path - decision: same host-testability constraint as 7.4 (unreachable without a successful `fp_*()` sensor call on Linux); the retry-then-give-up half of this behavior is covered via the same substitute, `test_persist_enrolled_users_locked_fails_after_exhausting_retries`, which confirms the persist helper reports failure and leaves the cache unchanged after exhausting retries. The sensor-side rollback call itself (`fp_delete_user()`) is not exercised by a host test; it is implemented per design.md's decision and reviewed by inspection (`sdf_services_enroll.c` `SDF_ENROLL_ACT_COMPLETE` handling)
- [x] 7.6 Unit test: delete/clear/permission-change with a simulated persistent NVS write failure report failure and trigger the red LED path, without a sensor-side rollback call - decision: same substitute as 7.4/7.5; `test_persist_enrolled_users_locked_fails_after_exhausting_retries` covers the shared persist-failure behavior these three paths all rely on. The three call sites' "leave cache stale-but-safe, no sensor-side rollback" handling (`sdf_services_delete_user`, `sdf_services_clear_all_users`, `sdf_services_change_user_permission`) is implemented per design.md and reviewed by inspection, not exercised end-to-end by a host test, for the same mock-UART reason
