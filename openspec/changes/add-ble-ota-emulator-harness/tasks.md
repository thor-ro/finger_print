## 3. Layer 1 — signature cases

- [x] 3.1 Implement a writer that streams the staged image through `sdf_ota_begin()` / `sdf_ota_write()` / `sdf_ota_verify_and_commit()` in the same call order the companion transport uses (spec: `ota-signature-emulator-gate` — Driven through the OTA session API). - [x] 3.2 Case: tampered. Flip one byte in a loaded segment, then **recompute the segment checksum byte and the appended SHA-256** so the image is internally consistent, keeping the original stale signature sector. Assert commit fails, `OTA_SIGNATURE_INVALID` is emitted, and the boot partition is unchanged (spec: Tampered Image Rejected; D3). Without the integrity repair this case is rejected by `process_checksum` before signature code ever runs (`esp_image_format.c:215-232`) and tests nothing. Evidence: `scripts/ota_signature_gate_prepare.py`'s `generate_tampered_repaired_image()` flips one byte inside a loaded segment and repairs the checksum byte and appended SHA-256 (verified against a real signed binary: exactly 34 bytes differ, trailing 4096-byte signature sector untouched); real-gate boot log shows `CASE 1 (tampered): rejected as expected` with `boot_partition_changed=0` and an `SDF_AUDIT_OTA_SIGNATURE_INVALID` audit event observed.
- [x] 3.3 Case: foreign key. Substitute the trailing 4096-byte signature sector and assert commit fails and the boot partition is unchanged (spec: Image Signed With A Different Key Rejected). Evidence: real-gate boot log shows `CASE 2 (foreign key): rejected as expected` with `boot_partition_changed=0`.
- [x] 3.4 Assert the foreign-key image carries a structurally valid signature block before the run, so its rejection demonstrates trust-anchor enforcement rather than a parse failure (spec: Rejection is attributable to the key, not to malformation). Evidence: prepare-time log `Foreign-signed artifact structural check: espsecure v5.3.1 / Signature block 0 is valid (ECDSA).`
- [x] 3.4a Assert the tampered image passes the header, segment, checksum and appended-hash checks and fails only at signature verification, so its rejection is not the image checksum in disguise (spec: Rejection is not the image checksum in disguise). Evidence: `assert_tampered_repair_only_breaks_signature()` runs at prepare time and logs `Tampered-and-repaired image self-check (task 3.4a): rejected only by a signature digest mismatch, not by checksum or appended-hash malformation`; independently corroborated by task 4.4, where the same tampered image is *accepted* once signature verification alone is compiled out.
- [x] 3.5 Case: valid. Write the staged image unmodified and assert commit succeeds and the boot partition advances (spec: Correctly Signed Image Accepted). Evidence: real-gate boot log shows `CASE 3 (valid): committed - boot partition updated, reboot imminent` and the terminal line's `valid=ACCEPT`.
- [x] 3.6 Order the run reject, reject, accept, and assert the accept case after a rejection demonstrates session recovery (spec: Session Recovery After Rejection; D5). Evidence: boot log case order is exactly CASE 1 (tampered, reject) -> CASE 2 (foreign key, reject) -> CASE 3 (valid, accept), each starting a fresh `sdf_ota_begin()` session after the prior rejection.
- [x] 3.7 Emit a machine-checkable terminal line that encodes how many cases ran and their outcomes, so a fixture that never reached the cases cannot exit zero (spec: Success is unambiguous).
